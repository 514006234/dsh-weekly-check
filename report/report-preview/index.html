一、三句话结论

  • 星数在这个生态里几乎不能用来判断能不能装。标签下星数最高的 8 个仓库（241.0k ★ 起）一个都不是可安装插件——是 harness 本体、简历生成器、图片上传工具这类蹭标签项目。
  • 被源码核验通过、列进 A 档的首选记忆插件只有 1 颗星。星数衡量的是传播，不是安全面。
  • 我们只深读了 2 个项目，其余 29 个之所以落在 B 档「需评估」，恰恰是因为还没读过源码——这一点写在报告里，不藏。

C 档 · 不建议（4 个）

不是"不好用"，而是权限面或副作用超出普通插件该有的范围。理由直接写在下面。

项目仓库星数为什么不建议
dsh-plugin-memory（记忆）LittleBlackTong/dsh-plugin-memory4源码级核验发现明确副作用：记忆库默认落在 ~/.memory（不在 .dsh 目录体系内），且自带自动提交器默认 intervalSeconds=60 / quietSeconds=60，会周期性对你的记忆库做 git add -A + commit。若记忆库恰好是某个既有仓库，会污染其提交历史（R3/R4）

B 档 · 需评估（18 个）

命中许可未声明（NOASSERTION）、AGPL/GPL 传染性、需要第三方密钥、或我们尚未读源码等风险面。完整版里逐条给出"为什么归 B"，以及把它升到 A 需要补哪一步核验。

五、我们明确不知道什么

  • 31 个项目里 29 个未做源码级审阅（这也是它们归 B 档的原因）；
  • 没有做动态沙箱、没有抓包、没有权限提升测试；
  • 免费模型只是单次实测快照，不是长期可用性承诺；
  • AGPL / GPL 对具体业务模式的合规影响，需要你们法务判断；
  • 个别插件的凭据读取路径与数据流向未核验（完整版附录 D 逐条列出）。

这一节是这份报告最重要的部分之一：一份不写"不知道"的选型报告，不值得信。
